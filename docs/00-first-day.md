# 第一天：90 分钟启动清单

目标：选定真实使用场景，确认环境，写下第一条问题；今天不要求做出 Agent。

## 0–15 分钟：定一个足够小的场景

- [ ] 从课程设计、实验室或个人项目中选一个你能持续改动的项目。
- [ ] 写下使用者：初期只有你自己。
- [ ] 选定一种问题：例如 Python 依赖与启动报错，或 FastAPI 接口测试失败。
- [ ] 在 [进度表](09-progress.md) 填写项目名称、资料来源与每周可投入时间。

完成标准：能说清“我每周会遇到什么问题，这个助手怎样减少查找和复现时间”。

## 15–35 分钟：创建独立环境

按 [环境指南](01-environment.md) 创建本项目的 `.venv`，确认解释器来自本目录。
尚未选择模型时不用填 API Key，也不需要本地下载大模型。

完成标准：记录 Python 路径和版本，不改动 G:\Learning 下其他项目的环境。

## 35–60 分钟：看一次上游请求如何流动

先读 [源码路线](02-upstream-reading.md)，打开上游 README 和 `project/rag_agent/graph.py`。
用自己的话记录：输入是什么、状态是什么、哪些节点会调用模型、在哪里决定再次检索。

今天只要求理解流程。上游安装与首次模型调用可留到本周后续学习时段。

## 60–80 分钟：记录一条实际问题

把 [问题模板](templates/incident.md) 复制到 `notes/incidents/`，填写一次自己遇到的报错。
暂时没有真实问题时，可在自己的练习项目复现一个人为故障，但必须标记“人工构造”。

不要把完整 `.env`、真实令牌、数据库密码或同学的个人资料放进知识库。

## 80–90 分钟：留下一条记录

- [ ] 用 [每日模板](templates/daily.md) 写三句话：今天理解了什么、卡在哪里、下一步做什么。
- [ ] 在进度表领取 `W01-01`。
- [ ] 若还没建立基线，保持“未运行”，不要填写通过率。

今天的成果应为：场景描述、环境记录、流程草图、一条问题记录、一篇学习日志。
